# RepoFix

[GitHub 仓库](https://github.com/NirvanaQJ/repofix)

可验证的 Python 仓库修复 Agent。目标是让开发者从固定仓库版本与缺陷描述得到可检查的补丁、可见测试反馈和执行轨迹，并通过独立隐藏验收判断是否真正修复。

**当前状态：仓库、README 和忽略规则已准备，产品未实施，实验未运行。** 没有可用安装包、CLI、API、测试命令或性能数据。设计与岗位分析完成不等于产品完成。

## 范围与核心输出（计划）

输入为仓库快照与 base commit、缺陷描述、允许修改路径、预登记测试 profile、模型配置和资源预算。先覆盖 Python/pytest、单仓库、单任务、有限多文件修改，不自动处理任意仓库环境或自主发布。

输出为绑定固定版本的补丁、修改说明、可见验证记录、预算消耗、停止／失败原因及轨迹。Agent 自报完成或可见测试通过不等于真正修复成功；独立评测器的隐藏目标测试、可信回归测试和修改范围检查共同决定最终判定。

## 技术方向与自研边界（计划）

- 使用 Python，自研有限 Agent Loop、上下文选择与预算、受控工具网关、补丁与失败语义；复用 Git、ripgrep、Python ast、pytest 与模型官方 SDK/HTTP 客户端，不重造通用 Agent 框架或编译器。
- 固定仓库版本；工具通过结构化参数和预登记测试命令执行，校验路径、修改范围、超时、预算及清理。测试代码仍可能执行任意操作，命令白名单不能代替执行隔离。
- 在受控 Docker 工作区运行不可信仓库代码，凭据留在受信任控制器；资源、网络、挂载及回收边界需实际验证，不能把容器描述为已验证的强隔离。
- 先实现独立 CLI 闭环；运行目录、JSONL 轨迹和 SQLite 元数据按需落地，后续才考虑 FastAPI/SSE 薄服务。以上均未实施。

## 独立交付与 RunProof

RepoFix 自行完成修复闭环和基础独立验证，不需要 RunProof 才能运行。RunProof 后续通过版本化 JSON 协议与外部 CLI 适配器采集补丁、轨迹和结果，承担批量实验与评分管理，不复制本项目 Agent 决策。两个项目分别交付，不互相导入内部模块，不共享内部源码，不使用 submodule 或符号链接耦合。

## 验证思路与验收边界（尚未执行）

先核查上游任务来源、许可证和固定版本，确认未修复时目标测试失败、参考修复后通过且原有回归仍通过。开发可见测试与隐藏验收隔离，参考补丁和隐藏答案不进入 Agent 可见快照；MVP 默认只允许修改源码，禁止通过修改测试或依赖伪造成功。

按固定任务、模型、工具权限与预算比较一次性补丁、基础 Loop 和改进 Loop，区分可见通过、隐藏修复、环境失败、超时及预算耗尽，保留全部尝试及失败证据。计划验收包括完整补丁闭环、跨文件修复、成功／失败／超时演示、路径与资源边界，以及干净环境复现。正式实验的任务规模、运行次数、工时和门槛仍是待实施计划；不预先承诺成功率或优于基线。

## 数据与发布约定

下列为实施时的路径约定，目前未创建这些目录：

- `experiments/<id>/runs/`、`experiments/<id>/raw/`：完整轨迹、原始请求响应、测试输出和未脱敏运行产物，仅本地保存并忽略。这细化了设计中的运行结果存放方式，不改变验证流程。
- `experiments/<id>/public/`：经人工审查、脱敏后可发布的 manifest、汇总报告、补丁和小型复现证据。原始运行文件不会因位于实验目录而自动获得发布许可。
- `runtime/`、`workspaces/`、`container-data/`、`upstream/`：本地运行、容器数据和下载的上游仓库，均忽略。
- 隐藏测试与参考答案应位于 Agent 不可见的独立验证位置，按进程权限和挂载边界隔离；`.gitignore` 不能控制读取权限。仓库内误放的 `private/`、`answers/`、`hidden-tests/` 等目录也忽略，但不能替代真正隔离。本轮不生成任务或答案数据。

[忽略规则](.gitignore)允许跟踪脱敏的 `.env.example`、源码、测试、依赖声明、真实锁文件、迁移和审查后的公开实验摘要；没有实际配置需求，暂不创建配置示例或依赖清单。岗位截图、个人规划与学习日记留在仓库外。

## 从哪里开始

下一步仅在开始实施时核对本机环境和首个任务的输入输出范围，再选择一个许可清楚、依赖轻的固定版本 Python 仓库，先验证无模型情况下的基线与参考修复。之后才逐步实现受控工具、有限 Loop 与独立验收，不以空模块、假测试或伪接口充当进度。

有真实可运行实现后，补充受支持环境、安装步骤、依赖及锁文件、配置说明、实际 CLI/API 用法、测试与复现命令、实验 manifest 和已知限制；在干净环境验证后再称其可用。发布产品前还需核对数据与上游许可、秘密及个人信息、所有权与许可证选择。当前仓库仅保存说明和忽略规则，不附 LICENSE，不提供尚未实现的命令。
